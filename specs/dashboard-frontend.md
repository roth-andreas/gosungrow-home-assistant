# Dashboard custom cards

Status: Normative  
Scope: Live flow, aggregate statistics, formatting, localization, interaction, and registration

## Common contract

- **REQ-CARD-001** — The bundle MUST register `gosungrow-energy-flow-card-v2`, `gosungrow-energy-summary-card-v1`, and `gosungrow-source-mapping-card-v1`, and advertise all three in `window.customCards`.
- **REQ-CARD-002** — Cards MUST reject missing required entity configuration, render in shadow DOM, escape all interpolated user/entity text, use Home Assistant theme variables, and rerender on `hass` updates.

## Live energy flow

- **REQ-CARD-003** — The flow card requires the ten live metrics in [domain-model.md](domain-model.md), renders PV, grid, home, and battery nodes plus five directional edges, and switches to compact layout below 700 px effective width.
- **REQ-CARD-004** — Complete automatic node values MUST use these directional formulas: PV=`PV→load + PV→grid + PV→battery`; grid=`grid→load - PV→grid`; home=`PV→load + grid→load + battery→load`; battery=`battery→load - PV→battery`. A formula is complete only when every listed operand is available, finite, and power-unit compatible. A genuine numeric zero is valid; a missing, pruned, unresolved, or invalid operand MUST NOT count as zero. Complete compatible formulas retain their existing precedence over automatic direct values.
- **REQ-CARD-005** — If a node entity is manually selected and differs from its `automatic_entities` entry, its direct entity state MUST replace the computed node value; an unavailable manual value MUST NOT silently fall back to a different source. Otherwise the card MUST use the complete formula under REQ-CARD-004, then an eligible verified direct total if the formula is incomplete, then unavailable if neither exists. Direct fallback verification MUST use the shared `source_policy` contract in REQ-SRC-031 rather than an independent guess from entity naming or numeric state. Direct fallback MUST satisfy the node's power-unit and presentation-sign contract. In particular, the opposite published legacy battery sign MUST NOT be silently interpreted as the battery presentation sign under REQ-DOM-015. These rules MUST NOT change published measurements, battery-direction status, route activity, or duplicate-label suppression.
- **REQ-CARD-006** — A flow is active only above absolute `0.01`. Active line width scales as `3.4 + min(magnitude,6)×1.2`; inactive edges and labels are hidden. In the wide layout, an active PV→battery label MUST be hidden when the available battery node equals the negative route value within absolute difference strictly below `0.01`, and the available battery→load route has absolute value at most `0.01`. An active battery→load label MUST be hidden under the symmetric condition: the available battery node equals the route value within absolute difference strictly below `0.01`, and the available PV→battery route has absolute value at most `0.01`. Suppression requires finite values with identical nonempty power units. Otherwise active route labels MUST remain visible. Compact layouts MAY omit route labels but MUST retain battery node information.
- **REQ-CARD-007** — Entity values MUST format with current unit, localized number formatting, adaptive precision, and explicit unavailable text. Clicking a configured node MUST emit `hass-more-info` for that entity.
- **REQ-CARD-019** — In both layouts, the battery power value MUST be visually grouped beside the battery icon with a visible localized “Battery power” caption. It MUST NOT occupy the PV→battery route or another route-label position. Power, direction status, and state of charge MUST remain distinct and readable without overlap. Accessible text MUST identify the battery power caption, formatted value, and direction status. Existing node-value selection, formatting, unavailable handling, and more-info interaction MUST remain governed by REQ-CARD-004, 005, and 007.
- **REQ-CARD-020** — Battery direction status MUST use the current PV→battery charge value `C` and battery→load discharge value `D`, independently of a manually selected battery node value. When both flows are available, finite, nonnegative, and have identical nonempty power units, status MUST be “Discharging” when `D−C > 0.01`, “Charging” when `D−C < −0.01`, “Idle” when both values are at most `0.01`, and “Balanced flows” otherwise. Missing, invalid, negative, or incompatible flow inputs MUST produce “Direction unavailable”. Status MUST update on Home Assistant state changes, support `en`, `de`, `sv`, and `es`, follow REQ-CARD-016–017, and use label keys `battery_power_caption`, `battery_status_charging`, `battery_status_discharging`, `battery_status_idle`, `battery_status_balanced`, and `battery_status_unavailable`.

## Energy summary

- **REQ-CARD-008** — Summary metrics and order are production, consumption, to grid, from grid, to battery, from battery with colors `#f59e0b`, `#38bdf8`, `#8b5cf6`, `#cbd5e1`, `#ec4899`, `#14b8a6`. Display permission MUST follow REQ-SRC-029 and REQ-CARD-021 independently of whether a saved mapping exists.
- **REQ-CARD-009** — Periods are day, month, year; default bucket counts are 14, 12, 5 and configured counts MUST be integers 1–60. For displayed series, the browser MUST request Home Assistant `recorder/statistics_during_period` daily rows with types `max`, `state`, and `sum` for all views. A withheld source's statistics MUST NOT enter the metric's displayed series.
- **REQ-CARD-010** — Permitted completed daily sensors use recorder `max` when finite, then `state`, then `sum`. The current day's recorder row MUST be ignored and replaced with the permitted live daily entity value; an unavailable live value remains absent.
- **REQ-CARD-011** — Day charts keep permitted daily buckets; month and year charts sum permitted completed daily buckets plus today's permitted live value into calendar month/year. Missing baseline on an early installation MUST retain the first observed completed day rather than compute a delta. Source changes MUST NOT merge or backfill different source histories under one metric.
- **REQ-CARD-012** — Invalid/missing live and recorder data and withheld series MUST remain absent. Empty results show statistics-unavailable/no-statistics or the applicable source-review state and MUST NOT invent zero buckets. Withholding or changing a dashboard source MUST NOT delete, rewrite, or relabel Home Assistant recorder history.
- **REQ-CARD-013** — Statistic starts accept ISO timestamps and millisecond epoch values. Buckets are generated in local calendar time, ordered chronologically, trimmed to the configured count, and relabeled without refetch when locale/date preference changes.
- **REQ-CARD-014** — Day labels follow Home Assistant `date_format`: `DMY` day/month, `MDY` month/day, `YMD` uses month/day for compactness, `system` uses system locale, `language`/missing follows language locale. Month uses localized short month and year uses localized two-digit year.
- **REQ-CARD-015** — Bars MUST be keyboard focusable images with localized ARIA labels and tooltips. Tooltip rows include every available configured metric permitted by REQ-CARD-021 in contract order with its color, label, formatted value, and applicable persistent source warning.

- **REQ-CARD-021** — The source presentation policy in REQ-SRC-028–032 MUST apply to current totals, day/month/year charts, historical series, tooltips, and native fallback. Display cards MUST consume the shared `source_policy` record for their target and canonical metric, consistently with the mapping card and effective selected entity, rather than infer verification independently. A withheld daily source MUST contribute neither live values nor recorder values to that metric and MUST show an actionable unavailable/review reason rather than a numeric total. An otherwise usable unverified manual source MUST retain a persistent visible and accessible warning wherever its values are presented, including historical views. Missing current state does not by itself invalidate otherwise permitted completed recorder rows. Once a valid replacement is explicitly adopted, only that replacement's eligible history MUST be used; this MUST NOT imply repair of the former source's historical data. Native-card withholding and restoration MUST use REQ-SRC-032's template and metric-owned paths so one affected series can change without losing other permitted series or layout. Native fallback MUST retain selection metadata under REQ-DASH-042 without treating retained policy or presentation templates as fresh eligibility evidence.

## Localization

- **REQ-CARD-016** — Explicit card labels override built-in labels. Runtime locale lookup order is full Home Assistant/browser locale, base language, then English.
- **REQ-CARD-017** — The frontend MUST support the same `en`, `de`, `sv`, `es` semantics as server-generated labels and preserve English fallback.
- **REQ-CARD-018** — The delivered dashboard module MUST be self-contained with no third-party runtime imports. Evaluation MUST synchronously register the energy-flow, energy-summary, and source-mapping custom elements and their `window.customCards` metadata. Re-evaluation or upgrade MUST tolerate earlier compatible element and metadata registrations without throwing or duplicating entries.

## Prohibited behavior

- Summing a current-day recorder value together with the live daily value.
- Treating unavailable series as zero.
- Replacing manual node readings with computed values.
